# Proliferative heterogeneity in tumour-infiltrating exhausted CD8⁺ T cells

Code, models and curation tables for the PhD thesis *Proliferative heterogeneity within
tumour-infiltrating exhausted CD8⁺ T cells*, University of Rome Tor Vergata.

The repository holds the analysis scripts, the GINsim model files and the prior-knowledge-network
curation tables that underlie the Methods chapter. Folder names and file numbering follow the
Methods subsections so that each reported step can be traced to the code that produced it.

## What is not here

- **No expression data.** All datasets are public; accessions are listed below and in the Methods.
- **No patient-level data of any kind**, and no patient identifiers.
- **No intermediate objects** (`.h5ad`, `.rds`, Matrix Market exports). These are large and are
  regenerated by the scripts.
- **No thesis figures.** The repository holds the code that produced them, not the images.

## Layout

```
analysis/    single-cell and spatial analysis code, numbered in run order
models/      GINsim network files and the Boolean simulation results
curation/    prior-knowledge-network interaction tables
panels/      gene panels used for module scoring
```

## Input data

Scripts read from a folder you provide. Set the `DATA_ROOT` environment variable, or edit the
fallback near the top of each script:

```bash
export DATA_ROOT=/path/to/your/data      # Linux / macOS
setx DATA_ROOT "D:\path\to\your\data"    # Windows
```

Absolute paths from the original machine have been replaced by `DATA_ROOT`, but the subfolder
names below it are the ones used during the analysis and are not a prescribed layout. Expect to
adjust them.

## Honest notes

These are the things that will not work if you run the repository blind.

- **Notebook 07 does not run top to bottom.** One cell saves a variable that is never created,
  one reads from a second drive, and one deletes an object that later cells use. Run cells
  selectively. The final tumour-only export block in that notebook is reconstructed — the exported
  files exist and were used, but the cells that produced them were not preserved. The block is
  labelled as such in the notebook.
- **`AddModuleScore` draws control genes at random.** Scripts 11, 15, 16 and 18 set no seed, so a
  re-run moves a small number of borderline cells between configurations. Script 17 sets
  `set.seed(123)`. Counts will differ slightly from those reported; directions and thresholds do not.
- **Script 09 clusters at resolution 0.50.** That solution is not the one reported. The reported
  clustering is resolution 0.27, applied in script 10. Script 09 is kept because it builds the
  `scVI_snn` graph that script 10 requires.
- **Script 10 is reconstructed from the R command history** of the session; the script was not
  saved at the time. The commands are those that were run, with repeated attempts removed. The
  session first clustered at resolution 0.25 and wrote marker tables, then re-clustered at 0.27 and
  overwrote them; only the 0.27 tables survive. A metadata column named `cluster_res025` holds the
  0.27 identities.
- **The full-atlas clustering in script 08 (resolution 0.25) is not reported** in the thesis, which
  clusters only the tumour-only atlas. It is retained because it was part of the original script.
- **Thresholds differ numerically between scripts 11 and 15.** Both recompute module scores and
  percentile thresholds per analysis object, as the Methods describe. Because z-normalisation runs
  within dataset over different cell sets, the printed thresholds are not identical.
- **Script 20 has a `gene_set_label` toggle.** Set it to `"top100"` to reproduce the reported
  analysis.
- **Script 19 builds its cycling exclusion set at run time** from MSigDB via `msigdbr`, so the gene
  list is not in the file. The resolved list is written to
  `Standardized_cellcycle_exclusion_union_Hallmark_Reactome_GOBP.txt` in the output folder.
- **Curated interactions (181) exceed network edges (162).** Some curated interactions merge during
  integration into the PKN.

## Models

`models/` holds the five module networks, the integrated prior-knowledge network (108 nodes,
162 interactions), and the reduced executable Boolean model (45 nodes, 81 interactions, 11 inputs).
Module networks sum to more nodes than the integrated network because nodes shared between modules
merge on integration.

`scenarios_and_stable_states.csv` records the eight simulation scenarios: the eleven input settings
and the resulting stable-state values for each. Node identifiers use the ASCII forms of the
executable model (`IFNg`, `TGFb`, `NFkB`, `JAKSTAT3_Pressure`, and so on); update rules are in
Table 1 of the thesis.

Files are GINsim `.zginml`. There is no SBML-qual export.

## Curation

`curation/` holds the prior-knowledge-network interaction tables, one CSV per module plus the
source spreadsheet. Columns follow the SIGNOR schema.

The `EVIDENCE_SOURCE` column distinguishes three kinds of entry:

| Value | Meaning | n |
|---|---|---|
| `SIGNOR` | SIGNOR-derived, carries a SIGNOR identifier | 103 |
| `manual_literature` | manually curated, carries a PubMed identifier and evidence sentence | 60 |
| `model_abstraction` | module-level functional dependency, not a molecular interaction | 18 |

In the source spreadsheet this distinction is held in cell fill colour, which does not survive
conversion; `EVIDENCE_SOURCE` is derived from the record contents instead. One row
(module 3, `HIF1A → Glycolysis`) is coloured as manually curated but carries a SIGNOR identifier
and is classified here as `SIGNOR`.

## Panels

`panels/gene_panels.csv` holds every gene panel used for module scoring, with the Methods
subsection each belongs to. Panels with the same name differ between subsections — the exhaustion
panel is nine genes in 4.1.7, twelve in 4.1.9 and ten in 4.1.11 — so panels are keyed by section,
not by name alone. The pseudobulk contrasts in 4.1.10 use extended panels, also listed.
